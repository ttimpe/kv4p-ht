# Bench recovery runbook — 2026-07-21 (delete after use)

The node (192.168.2.58, "tt-test") went dark after an OTA flash of debug build
900. Its bootloader predates the Rust tree (C→Rust migration happened over
OTA), so it has no rollback. This session's tree now contains build 901:
debug endpoints (`/api/uplinklog`, `/api/crashlog`) **plus** the heap fixes
(decoder pauses during every TLS handshake, NEMO buffers halved and capped).

## Step 0 — no cable needed, try first

Check whether the open WiFi AP **`kv4p-rx-setup`** is broadcasting near the
device. If yes, the build-900 firmware is alive and only STA is broken:
connect to the AP, open the device's web UI (its AP-side IP), and POST the
new image to `/update` — no serial needed:

    curl -X POST --data-binary @kv4p-debug-901.bin http://<ap-ip>/update

## Step 1 — serial flash (the full fix)

USB cable into the kv4p, then from this machine:

    cd microcontroller-src/rx-streamer-rs/firmware
    export PATH="$HOME/.cargo/bin:$PATH"
    . ~/export-esp.sh
    export RUSTC_BOOTSTRAP=1
    cargo run --release        # espflash flash --monitor, per .cargo/config.toml

This writes bootloader + partition table + app:
* the new bootloader has `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`, so OTA
  rollback works end-to-end from now on;
* the partition table is byte-identical to the C one — NVS (WiFi, channels,
  tokens) survives;
* the serial monitor shows why build 900 failed to boot (worth capturing
  before flashing: just `espflash monitor` first if curious).

## Step 2 — verify the fix on the bench

1. Boot with monitor attached; wait for `[wifi] connected`.
2. `curl http://<ip>/api/crashlog` — expect `resetReason` + any prior crash.
3. Switch to the NEMO channel (SWB K4, channel index 9) with the wss uplink
   configured. Expected serial/uplinklog sequence per connect:
   `decoder paused for handshake` → `ws client started` → `ws event:
   connected` → `decoder resumed` → `hello sent` → `hello acked`.
4. Leave it decoding NEMO ≥15 min. Watch uptime (no reboots), heap in
   `/api/status`, and `/api/crashlog` (should stay empty). If it still
   crash-loops, `/api/crashlog` now names the killer (panic message or
   failed-alloc size) — that's the next bug to fix, remotely visible.

## Artifacts

* Fixed image: scratchpad `kv4p-debug-901.bin` (rebuilt any time with the
  commands above + `espflash save-image --chip esp32 target/xtensa-esp32-espidf/release/kv4p-rx-streamer <out>.bin`)
* Stranded image for post-mortem: scratchpad `kv4p-debug-900.bin`
* Build numbers are parked at 900+ so the auto-updater won't overwrite them;
